## Issues Found

### Critical

**1. Super-admin API routes have NO authentication or authorization checks**

All 13 routes under `app/api/admin/` lack any call to `auth.getUser()`, `verifySuperAdmin()`, or equivalent. Any unauthenticated request can hit these endpoints:

- `app/api/admin/announcements/route.ts`
- `app/api/admin/audit/route.ts`
- `app/api/admin/config/route.ts`
- `app/api/admin/diagnostics/route.ts`
- `app/api/admin/flags/route.ts`
- `app/api/admin/leads/route.ts`
- `app/api/admin/licenses/route.ts`
- `app/api/admin/organizations/[id]/route.ts`
- `app/api/admin/organizations/route.ts`
- `app/api/admin/password-management/route.ts`
- `app/api/admin/stats/route.ts`
- `app/api/admin/users/[id]/route.ts`
- `app/api/admin/users/route.ts`

**Impact:** Full read/write access to user data, org data, feature flags, platform config, and audit logs without any authentication. This is exploitable in production.

**Recommended fix:** Add `verifySuperAdmin()` guard at the top of every handler function in these files. The pattern already exists in `lib/admin/auth.ts`.
