### Warning (4)

#### 1. ESLint `.eslintignore` not respected (flat config migration needed)

**Severity:** Warning
**Details:** The `.eslintignore` file contains `.claude/` but ESLint 9 flat config ignores `.eslintignore` by default. This inflates lint counts from ~336 real issues to ~1557 total because 3 worktree copies are also scanned.
**Recommendation:** Migrate ignore pattern to `eslint.config.mjs` using the `ignores` array:
```js
{ ignores: ['.claude/**', '.next/**', 'node_modules/**'] }
```

#### 2. AI routes use `auth.getSession()` instead of `auth.getUser()`

**Severity:** Warning
**Files:** All 8 routes under `app/api/ai/`
**Details:** Supabase recommends `auth.getUser()` over `auth.getSession()` for server-side auth checks because `getSession()` reads from the JWT without validating it against the auth server. An expired or tampered JWT could pass `getSession()` but fail `getUser()`.
**Recommendation:** Replace `supabase.auth.getSession()` with `supabase.auth.getUser()` in all AI API routes.

#### 3. `@ts-nocheck` directives still present

**Severity:** Warning
**Files:**
- `app/api/email/inbound/route.ts` — has `@ts-nocheck` at line 1
- `app/api/email/send/route.ts` — has `@ts-nocheck` at line 1
**Details:** ESLint flags these as `@typescript-eslint/ban-ts-comment` errors. These bypass all type safety in these files.
**Recommendation:** Remove `@ts-nocheck` and fix the underlying type errors.

#### 4. `password_reset_tokens` reference in code comment

**Severity:** Info
**File:** `app/api/admin/password-management/route.ts:25-26`
**Details:** Comment references a nonexistent `password_reset_tokens` table. The table is `password_reset_config`. This is a TODO comment, not an active query, so no runtime impact.
