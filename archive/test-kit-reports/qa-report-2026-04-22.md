No file has more than 5 instances, so nothing breaches the "flag files with >3" threshold except `email/inbound/route.ts` (5). Worth a future pass to shape the normalised webhook payload as a proper `TablesInsert<'comments'>` type.

### Organization scoping
`app/api/company-admin/*` routes all enforce organization isolation, using one of two patterns:

1. Direct `.eq('organization_id', admin.organization_id)` on the query (e.g., `stats/route.ts`, `users/route.ts` GET).
2. Select-by-id then verify `targetRow.organization_id === admin.organization_id` before mutating (e.g., `users/[id]/route.ts`, `groups/members/route.ts`, `users/[id]/reset-password/route.ts`).

Pattern 2 is secure because `verifyCompanyAdmin()` has already authenticated the caller and the check precedes any mutation, but belt-and-suspenders would add `.eq('organization_id', admin.organization_id)` directly on the UPDATE/DELETE for defense in depth. Recommended for the `company-admin/users` PATCH flow in particular.

## Recommendations

In priority order:

1. **Rename `middleware.ts` → `proxy.ts`** before the Next.js 16 deprecation becomes a removal. Low effort, removes the build warning.
2. **Clean up the 7 `exhaustive-deps` warnings** so lint is zero-warning. Either `eslint-disable-next-line react-hooks/exhaustive-deps` with a rationale comment, or actually add the deps where safe. The topic is safe to touch because TS is clean and tests aren't bound to these call counts.
