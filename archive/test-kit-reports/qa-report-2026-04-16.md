### API Route Auth Coverage
**Result: ⚠️ WARNING — 1 route**

`app/api/email/inbound/route.ts` touches `permits`, `comments`, `activity_log`, and `email_queue` tables but does **not** call `supabase.auth.getUser()`. Instead, it authenticates via a shared webhook secret (`INBOUND_EMAIL_SECRET` env var).

**Assessment:** This is architecturally appropriate for a webhook endpoint — inbound email processing is not a user-authenticated flow. However, there is a conditional auth gap:

```ts
const secret = process.env.INBOUND_EMAIL_SECRET;
if (secret) {
  // validates token
}
// If INBOUND_EMAIL_SECRET is not set → no auth check, route is open
```

If the environment variable is unset (e.g., in a fresh staging deployment), the route accepts unauthenticated POST requests with full write access. This is a low-probability but real risk.

**Recommendation:** Change the guard from `if (secret)` to `if (!secret) return 401` to make authentication mandatory, not optional.
